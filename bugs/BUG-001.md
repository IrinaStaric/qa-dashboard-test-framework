# BUG-001 — Weak password policy: password field accepts lowercase-only passwords

## Description
The application allows setting and using passwords that consist only of lowercase letters for multiple user roles (Admin, Operator).  
The password field does not enforce any password complexity requirements, such as the presence of at least one uppercase letter, which weakens authentication security and does not align with common security best practices.

## Severity
High

## Environment
- Affected roles:
  - Admin
  - Operator
- Affected flows:
  - User creation / password configuration
  - Authentication (Sign In)
- Browser: Chrome, Safari
- OS: macOS

## Preconditions
1. A user account (Admin or Operator) exists or is being configured.
2. Password can be set or updated via UI or backend configuration.
3. No password complexity rules are visibly enforced.

## Steps to Reproduce
1. Create or update a user password using only lowercase letters (e.g. `passwordonly`).
2. Save the password configuration.
3. Navigate to the Sign In page.
4. Enter the lowercase-only password.
5. Submit the login form.

## Actual Result
- The system accepts a password consisting only of lowercase letters.
- Authentication succeeds without any validation errors or warnings.
- No indication is shown that the password is weak or insecure.

## Expected Result
- The system should enforce password complexity rules.
- Passwords should require at least one uppercase letter (and ideally additional constraints such as digits or special characters).
- The user should be blocked from saving or using weak passwords.
- A clear validation message should be displayed explaining password requirements.

## Security Consideration
Allowing lowercase-only passwords significantly reduces password entropy and increases the risk of brute-force or credential-stuffing attacks.  
This behavior weakens overall authentication security and may violate internal or industry security standards.
