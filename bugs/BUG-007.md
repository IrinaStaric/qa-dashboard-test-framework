# BUG-007 — Management Assets: Search can break records loading and exposes raw SQL/DB error to user

## Summary
Performing a search on **Management Assets** can cause the table to fail loading and show a modal error containing **raw SQL query text and database error details**.

## Environment
- App: QA Dashboard (local)
- Page: /managementAssets
- Browser(s): Chromium, Safari
- OS: macOS

## Preconditions
- Logged in as **Admin**.
- On **Management Assets** page.

## Steps to Reproduce
1. Navigate to **Management Assets** (`/managementAssets`).
2. In the search input, enter a value that triggers the issue (example: a partial string like `test`).
3. Submit the search
4. Observe the UI behavior.

## Actual Result
- UI shows **"Cannot load records"** and displays an error message that includes:
  - the raw SQL query text (e.g. `select ... from "assets" ...`)
  - DB/operator error details (e.g. `operator does not exist: uuid ~~ unknown`)
- Records do not load successfully.

## Expected Result
- Search should return filtered results (or "No results" state) without errors.
- UI should not expose raw SQL queries or internal DB error details.
- If an error occurs, a generic message should be shown, and details should be logged server-side only.
