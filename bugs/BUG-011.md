# BUG-011 — Logout does not revoke active session in other browser (no global sign-out)

## Summary
If a user is logged in on two browsers (e.g., Chrome and Safari) and logs out in one browser, the session in the other browser remains active and can continue accessing protected pages without re-authentication.

## Environment
- App: QA Dashboard (local)
- URL: http://localhost:5480
- Role: Admin (observed)
- OS: macOS
- Browsers: Chrome + Safari

## Preconditions
- Same user account logged in on Browser A and Browser B at the same time.

## Steps to Reproduce
1. Open the app in **Chrome** and log in.
2. Open the app in **Safari** and log in with the same user.
3. In **Safari**, click **Logout**.
4. Switch to **Chrome** (already logged in session).
5. Refresh the page or navigate to any protected page (e.g., `/managementAssets`).

## Actual Result
- Chrome session remains authenticated and continues to access protected pages.

## Expected Result
One of the following (needs product decision):
- Option A (Global logout): Logging out should terminate all active sessions for that account across browsers/devices.
- Option B (Current-session logout): Logging out only ends the current session (then this is expected behavior, not a bug).

## Impact
If global logout is expected, this is a security gap: user cannot quickly terminate all sessions (e.g., after using a shared/public device). If current-session logout is expected, behavior is acceptable but should be documented.

## Notes
- This report is created to confirm expected session policy (global vs per-session logout).
