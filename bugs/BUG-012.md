# BUG-012 — After logout, back navigation restores authenticated page and redirects to Assets without login (Safari)

## Summary
After logging out as Admin in Safari, using browser Back navigation (sometimes requiring multiple clicks) returns the user to a protected page (Assets) without re-authentication.

## Environment
- App: QA Dashboard (local)
- URL: http://localhost:5480
- Role: Admin
- Browser: Safari (WebKit)
- OS: macOS

## Preconditions
- Admin user is logged in

## Steps to Reproduce
1. Log in as Admin.
2. Navigate to `Assets` (or any protected page).
3. Log out.
4. After logout, click the browser **Back** button.
5. If needed, click Back again (observed behavior can require multiple clicks).

## Actual Result
- The application returns the user to a protected page without showing the login screen.
- User appears effectively re-authenticated / redirected into the app after logout.

## Expected Result
- After logout, any attempt to go back to a protected page must require authentication.
- Browser back navigation must not restore an authenticated state.

## Impact
This is a session handling issue that can lead to unauthorized access if a user logs out on a shared machine. It also suggests the logout flow may not invalidate session state consistently for browser history restoration.
