# BUG-013 — Protected page renders after logout when navigating back (Chrome)

## Summary
After logging out as an Admin user, navigating back using browser history allows a protected page (e.g., Assets) to render even though the user is no longer authenticated.

## Environment
- Application: QA Dashboard (local)
- Base URL: http://localhost:5480
- User Role: Admin
- Browser: Chrome (Chromium)
- OS: macOS

## Preconditions
- Admin user is authenticated
- User is currently on a protected route (e.g., Assets)

## Steps to Reproduce
1. Log in as an Admin user.
2. Navigate to a protected page (e.g., Assets).
3. Log out successfully.
4. Press the browser **Back** button.
5. Repicates with every page ( URL )

## Actual Result
- The protected page renders after logout when navigating back.
- Protected UI elements (page layout, records, navigation) are visible despite the session being terminated.
- Access control is applied only after the page has already rendered.

## Expected Result
- Protected routes must not render after logout.
- Session validation should occur before route rendering.
- Navigating back should redirect the user directly to the login page (or an access-denied state) without exposing any protected UI.
